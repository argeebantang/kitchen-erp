# 2026-11-24 — PWA: installable, full screen, offline banner

Week 12 roadmap item "PWA setup: installable on mobile with offline indicator". Follows the owner's "it doesn't feel
native" (see `2026-11-24-qr-transfers.md`). Builds on that task's phone layout (`AppShell`, the drawer), which
reached `main` with PR #42 before this branch was made.

## In plain words

- **Install it like an app:**
  - Android Chrome: ⋮ → **Install app**.
  - iPhone Safari: Share → **Add to Home Screen**.
  - Desktop Chrome: the install icon in the address bar.
- **What you get:**
  - An orange **K** icon. The browser tab shows it too, instead of the Next.js logo.
  - It opens **full screen**, with no address bar, and starts at the dashboard.
  - On Android, long-press the icon for a **Receive** shortcut.
- **Fits the phone:**
  - The bottom of the page is no longer hidden behind Safari's toolbar.
  - Nothing sits under the iPhone home bar or a landscape notch.
  - Scrolling past the end moves only the page, not the whole app.
  - No grey flash on tap.
  - Every field is 16px on a phone, so iPhones don't zoom in. The login page and the two search boxes were still
    14px.
- **No connection:**
  - A strip under the top bar: "You're offline. Nothing you save will reach KitchenERP until the connection is back."
  - "Back online" for 3 seconds when it returns.
  - Opening a page with no signal shows a KitchenERP "You're offline" page with **Try again**, instead of the
    browser's error.

## Decisions

| # | Decision | Rationale |
|---|---|---|
| P1 | **The service worker caches only the offline page.** No pages, API responses or stock | Showing yesterday's stock as if it were current is worse than showing nothing. Offline counting with sync is a separate, larger project |
| P2 | **The icon is the orange K badge, drawn as shapes and rendered with `sharp`** | No logo was supplied. Shapes, not text, so the result doesn't depend on installed fonts. To use a logo, replace the PNGs in `public/icons/` |
| P3 | **Icons declared in `metadata.icons`, not Next's `app/icon.png` file convention** | A metadata `icons` object overrides the convention, so the favicon silently disappeared |
| P4 | **White `theme_color`** | The phone's status bar runs into the white top bar, as native apps do |
| P5 | **Start at `/dashboard`; long-press shortcut to Receive** | Every role has a dashboard; outlets mostly open the app to receive |
| P6 | **The manifest, icons, `sw.js` and `offline.html` skip the login middleware** | Browsers fetch them without cookies, and a redirect to /login makes the app uninstallable. None of them holds data |
| P7 | **Out of scope:** offline counting with sync, push notifications, page caching | Each is its own task (agreed 2026-11-24) |

## What changed

**Installable**
- `app/manifest.ts` (new; Next serves it as `/manifest.webmanifest`).
- `public/icons/` (new): 64, 192, 512, maskable 512, Apple 180.
- `app/favicon.ico` removed (it was the create-next-app one).
- `public/sw.js` and `public/offline.html` (new).
- `components/pwa/ServiceWorkerRegister.tsx` (new).
- `app/layout.tsx`: `appleWebApp`, `icons`, `formatDetection`, and `viewport` (`themeColor`, `viewportFit: 'cover'`).
- `middleware.ts`: the matcher skips the PWA files.

**Fits the screen**
- `min-h-screen` → `min-h-dvh` in the login, error, global-error, not-found and unauthorized pages.
- `components/dashboard/AppShell.tsx`: `h-dvh`, safe-area padding, `overscroll-contain` on `main`.
- `components/dashboard/Sidebar.tsx`: `md:min-h-dvh`; the drawer pads for the home bar and notch.
- `app/globals.css`: no tap highlight.
- 16px on phones (`text-base sm:text-sm`) for the login inputs, `components/ui/SearchBox.tsx` and the sidebar
  search.

**Offline banner**
- `components/pwa/OfflineBanner.tsx` (new), shown by `AppShell` under the top bar.

**Database, API:** none.

**Configuration:** none. The icons were rendered once from a scratch script; `sharp` was already installed with
Next.js.

## How to test

On this computer (Chrome counts localhost as secure):
1. The tab shows the orange K.
2. DevTools → Application:
   - **Manifest:** KitchenERP, icons, no errors.
   - **Service workers:** `sw.js` activated.
   - **Cache storage:** one cache holding only `/offline.html`.
3. Install from the address bar: KitchenERP opens in its own window with no address bar.
4. DevTools → Network → **Offline**:
   - the amber "You're offline." strip appears;
   - reload and you get the K "You're offline" page;
   - back **Online** → **Try again** returns to the app, and "Back online." shows for 3 seconds.

On a phone (cloudflared tunnel):
5. Install it, as above. It opens full screen; on Android, long-pressing the icon offers Receive.
6. Receive and the count form: nothing hides behind the toolbar or the home bar, and tapping a search box doesn't
   zoom the page.

What I checked, in headless Chromium at iPhone size (390 × 844) and at desktop size (1280 × 800). Words only, no
screenshots; the test scripts live in my scratchpad, not the repo. Every check passed:

- **Installable**
  - Chrome's own installability check and manifest parser report no errors.
  - Every icon loads at its declared size.
  - The service worker is active at `/`, and its cache holds only `/offline.html`.
- **Fits the screen**
  - `viewport-fit=cover` is set.
  - The app frame is exactly the visible height (844 of 844).
  - Scrolling past the end is contained; no tap highlight.
- **Offline**
  - The banner appears offline, shows "Back online." on reconnect and clears after about 3 seconds.
  - An offline reload gives the branded page, and Try again brings the app back.
- **16px audit** (Receive, Transfers, Stock Requests and New, Daily Sales and New, Return, Dashboard, a transfer,
  with the drawer open): it found the two 14px search boxes. Fixed and re-run, it passes.
- **Regression at phone size**
  - Signed-out → login → back on Receive.
  - The drawer opens and closes.
  - The count form, without submitting: All arrived, − / + clamped at 0 and at what was sent, the reason buttons,
    the bottom bar text, and the sheet flush with the bottom edge.
- **Desktop unchanged**
  - The sidebar is 256 px and collapses to 64.
  - There's no ☰ button and no phone bar.
  - Fields stay 14px.
  - Confirm is a centred dialog.

Test data: one in-transit delivery for the count-form checks, plus the one the owner received while testing the QR
task. Both were reversed and removed, and Main Commissary's lots are back to their earlier quantities.

## Risks and follow-ups

- **Installing needs https.** It's fine on the real server and on localhost; on a phone during development it needs
  the tunnel.
- **iPhone has no install prompt.** People must use Share → Add to Home Screen. Worth a line in staff training, or
  a small "Install the app" hint later.
- **A stale `sw.js`:** browsers re-check it at least daily, and it caches one file, so the worst case is an old
  offline page. Bump `CACHE` in `sw.js` whenever `offline.html` changes.
- **Next steps if wanted:** a real logo in `public/icons/`; offline counting with sync; push notifications.
